# 渲染与质量验收

## 渲染器行为

1. 加载最终 `image`；存在分层输入时，用 `base_image` 作为首帧，用 `draw_image` 作为唯一动态路径源。
2. 解析字幕安全区，并拒绝进入其中的最终画面内容、声明区域或笔尖路径。
3. 采样路径源边缘背景，分别检测深色墨线和非背景内容。
4. 把像素聚合到小网格中，只用于路径规划。
5. 把粗墨线细化为单格中心线，同时保留完整墨线遮罩用于像素揭示。
6. 在有序 `object_regions` 边界处分割相连中心线，完成当前对象的全部组件后再进入下一个对象。文字场景按 `hand_regions` 顺序，组内先聚合行，再从上到下排列行、从左到右排列组件。
7. 把完整路径首次访问顺序传播到附近彩色内容，并保留每个规划格最近的真实路径种子坐标。
8. `direct_draw` 场景增加稀疏填色覆盖路径。把粗规划时间图转换为像素级揭示：每个动画像素选择几何最近路径种子，种子到达后才开始，并在 0.2 输出帧内完成单像素径向微抖动；孤立近背景颗粒从首帧作为静态纹理显示。禁止方格复制、远处出现、拖尾淡入和模糊光晕。
9. 传统模式先画黑线，再沿同一路径恢复原色。
10. `direct_draw` 模式一次显示原色，并在完整定格期间移除手部。
11. 把实体马克笔笔尖放在当前路径点。
12. 移除手部并保持完整静帧。

首次访问顺序必须使用包含 DFS 回溯的完整马克笔路径索引。不能用唯一格数量给画面计时、同时用更长的完整路径给手计时。粗线和填充继承最近中心线种子在完整路径上的步骤，因此无需让手扫描每个像素。

相同项目 JSON 和源素材必须产生确定性相同的路径与时间。

## 调节指南

| 现象 | 修复方式 |
| --- | --- |
| 空白背景产生大量路径 | 提高 `content_distance`；重新生成更平坦的背景。 |
| 浅色轮廓丢失 | 提高 `ink_threshold` 或重新生成更深轮廓。 |
| 彩色填充被当成黑线 | 降低 `ink_threshold`。 |
| 手部移动块状明显 | 降低 `grid_cell`；像素揭示边界本身仍必须平滑。 |
| 头发或填色呈方格阶梯 | 拒绝成片；确认使用像素级最近种子揭示，不能只靠降低网格掩盖。 |
| 填色呈硬多边形块 | 确认使用严格受限的径向种子延迟和单像素微抖动；拒绝整块布尔揭示或透明度羽化。 |
| 笔尖离开后内容继续出现 | 使用笔尖锁定揭示，移除提前或拖尾羽化，时间滞后不超过 0.2 帧。 |
| 笔在别处时彩色区域出现 | 降低 `fill_route_stride` 或 `grid_cell`，直到最大种子距离通过；不能仅放宽限制。 |
| 空白纸面斑点慢慢出现 | 只动画化有活动规划格支持的内容；孤立近背景颗粒从首帧静态合成。 |
| 头发画一半后跳去别处 | 添加有序 `object_regions`，浓密对象优先，并确认路径在边界处分割。 |
| 手在小斑点之间抖动 | 提高 `grid_cell` 或重新生成无噪点画面。 |
| 部分颜色直到末帧才出现 | 降低 `content_distance` 或简化源图。 |
| 用手掌而不是笔尖描线 | 重新运行 `prepare-hand` 修正 `tip_anchor`。 |
| 手部过大 | 降低 `hand.width_ratio`。 |
| 手持续描完整个画面 | 把框架移入 `base_image`，`draw_image` 只保留 1–3 个关键组，并缩短 `write_seconds`。 |
| 文字或公式写一半离开 | 扩大单个 `hand_regions` 以包含完整组，并验证组顺序单调。 |
| 公式从最右侧开始 | 按文字行聚类后依据左边界排序，不能依据最高像素排序。 |
| 标签碰到坐标轴、箭头或刻度 | 移出碰撞图；1920×1080 下保留 18–24 px 间距。 |
| 内容进入字幕区 | 重新构图到安全线以上；不能只移动字幕。 |
| 场景完成后无阅读时间 | 增加 `duration` 或 `hold_seconds`。 |
| 场景 MP4 存在但为 0 字节或只有几十字节 | 视为中断或损坏的检查点。重新渲染该场，并在拼接前用 `ffprobe` 验证。 |

## 中断渲染恢复

把每个场景片段、route JSON、路径预览和阶段图都保留为检查点。中断后先枚举预期场景 ID，并逐个验证片段。有效检查点必须能被 `ffprobe` 打开，包含符合预期宽高和 fps 的视频流，并且时长合理；文件存在和编码器退出成功都不够。只要分镜和素材没有变化，就只重渲染缺失或无效场景。

所有场景片段通过上述检查后才能拼接，再单独验证拼接后的无声母版。无声渲染报告和最终封装报告要分开：后者必须证明 H.264/AAC 流、字幕烧录、最终时长和音轨数量。恢复失败时保留已有证据，方便下一次从最后一个已验证边界继续。

## 验收门

| 项目 | 必须通过 | 硬失败 |
| --- | --- | --- |
| 口播完整性 | 所有分句在项目与字幕中按顺序出现一次。 | 缺失、重复、改写或重排。 |
| 场景图 | 浅色干净背景、深色清晰边界、合理强调色、无手和伪文字。 | 手被烘焙、水印、畸形文字、浑浊背景或主体裁切。 |
| 参考图适配 | 抽象媒介、线条、配色、纹理、形状语言和密度与 `style_profile` 一致。 | 只复制颜色或丢失参考图视觉语法。 |
| 原创性 | 主体、轮廓、姿势、道具、取景和构图重新设计。 | 可识别身份、Logo、标志物、精确姿势或布局被复现。 |
| 手绘来源 | 需要手绘时保留 ImageGen 生成的结构笔迹和模拟媒介不规则性。 | 完全程序矢量画面或用程序噪声冒充手绘。 |
| 路径覆盖 | 路径触及所有重要主体和关系。 | 主要主体、箭头或图示未访问。 |
| 手部经济性 | 手只写关键组，完成后离场供阅读。 | 手描标题、面板、坐标轴、网格或几乎全程活动。 |
| 文字组完整性 | 一个组完整写完后才进入下一个。 | 半个词或公式被放弃后返回补写。 |
| 人类书写顺序 | 多行从上到下，拉丁文字与公式从左到右。 | 行交错或公式从右侧开始。 |
| 标签间距 | 标签避开几何、其他标签和字幕区。 | 字符被线条遮挡或标签互相覆盖。 |
| 字幕安全区 | 下方 24% 只有背景，所有内容与路径在其上方。 | 任一画面痕迹或路径进入安全区。 |
| 手部对齐 | 实体笔尖准确接触当前路径，尺寸合理。 | 手掌、手指或悬空笔身描线；有绿色边缘。 |
| 揭示同步 | 像素分配给附近真实路径种子，到达后出现，0.2 帧内完成。 | 手与画面使用不同时间、远处出现或拖尾淡入。 |
| 揭示分辨率 | 浓密内容使用覆盖路径与像素级边界。 | 网格方块、阶梯、硬多边形、模糊光晕或无路径支持的填色。 |
| 对象完整性 | 头发和优先对象完成后才进入下一区域。 | 对象画一半后跳走并返回。 |
| 绘制顺序 | 传统模式黑线先于颜色；颜色沿既定路径。 | 通用擦除、随机块、整图淡入或结构前上色。 |
| 最终定格 | 末帧匹配批准静帧，无手且至少保持 0.8 秒。 | 手仍存在、内容不完整或立即切走。 |
| 时间 | 场景时长来自口播估算或权威 TTS。 | 使用与口播无关的任意固定时长。 |
| TTS 同步 | 场景、合并音频和字幕使用同一帧对齐时钟。 | 文本估算覆盖真实音频时间。 |
| 内嵌字幕 | 一至两行字幕清晰、完整且位于下方安全区。 | 裁切、不可读、重复、缺失或遮挡主体。 |
| 动作 | 手的位置随可见内容变化。 | 平移、缩放、抖动、溶解或统一全图动作。 |
| 技术输出 | H.264 MP4 可播放，分辨率与帧率正确，音轨状态准确。 | 尺寸错误、文件损坏、音轨异常或缺少证据。 |

## 证据检查

以正常播放比例检查每张 `*-path.jpg`。红线和阴影标出字幕安全区，任何路径或画面痕迹都不能触碰或穿过。分层文字场景要求 route JSON 的 `group` 与 `line` 顺序单调；同一行中新进入组件的首个 x 坐标不得递减。除阶段图外，还要检查至少一个公式的早期帧，确认从最左侧开始。

逐张从左到右检查 `*-stages.jpg`，确认静态框架、逐组完整书写、`direct_draw` 下无重复上色，以及最终无手完整画面。打开第一场片段和最终合并 MP4；拼接前逐个检查所有场景片段的视频流、预期宽高/fps 和合理时长，确认硬切且每场不丢末帧。

检查至少一个浓密填充的连续帧：新像素必须靠近该帧扫过的路径点，不能在旧笔位周围继续淡入。每场报告必须满足 `reveal_sync.mode = nib-locked`、`max_seed_distance_px <= limit_px`、`max_temporal_lag_frames <= 0.2`。使用 TTS 时检查第一个词、所有场景切点和最后一个词，并确认只有一条音轨且字幕可见同步。

`reference-adapted` 项目需把参考图与至少三张代表场景并排检查，确认抽象特征一致、内容构图明显不同。若保留了来源对象关系、姿势或焦点布局，必须更换视觉隐喻重新生成。

在最终备注中记录任何参数修复、字幕带清理或恢复重渲染。如果清理了下方像素，说明为什么它们是可丢弃的背景而不是有意义的主体内容。不能只根据编码器退出成功或文件存在就接受渲染。

在最终说明中记录参数修复。不能仅凭编码成功或文件存在就验收。
